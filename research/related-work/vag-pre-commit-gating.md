# Verifier-as-Gatekeeper (VaG) — detailed notes

**Paper:** *When Self-Evolution Backfires: Pre-Commit Gating against Skill Contamination in LLM Agents* — Linfang Shang (eq. contrib.), Ming Xu (eq. contrib.; corresponding), Yiding Sun, Tianle Xia, Lingxiang Hu, Lan Xu, Ning Zheng (all Tencent). arXiv:2608.05810, cs.AI (cross-list cs.CL); v1 6 Aug 2026, v2 17 Sep 2026. Preprint; no venue stated. No VaG code link in the paper; the only GitHub link is the agent framework it builds on (Agentica, github.com/shibing624/agentica). Reviewed 2026-10-12.

**Read depth:** full text of the arXiv v2 PDF (9 pages: main text and references). The "Supplementary Material" it cites for implementation details and the full git-skill contamination chain is **not** in the arXiv version, so I could not check those details. There is no limitations section.

## Mechanism

- **Setting:** each round, a frozen-weight ReAct terminal agent solves tasks with the current skill pool M_{r-1} in its system prompt. Its trajectories are then distilled into new natural-language skills S_r ~ π(·|M_{r-1}) (frontmatter = name, trigger condition, body; then free-form guidance), and M_r = M_{r-1} ∪ G(S_r). G is the admission operator. G = identity is "Ungated", which the authors equate with Voyager/AHE-style admission.
- **Contamination taxonomy:** *individual* (singleton gain g({s}) < 0), *combinatorial* (two skills that are each harmless are harmful together), *systemic* (the pool-size curve P(k) is shaped like an inverted U, with a "capability–contamination tipping point" at k*).
- **Irreversibility argument (Eq. 5):** later skills are distilled with earlier skills in context, so a defective skill s leaves descendants desc(s). Removing only s therefore does worse than removing s together with its lineage. That lineage cleanup needs provenance that "existing skill libraries do not record". From this the authors conclude admission must be **pre-commit**, not post-hoc. It is a short argument plus an empirical demonstration, not a formal proof.
- **Progressive trust hierarchy Cold ≺ Warm ≺ Hot:** new skills start in Cold, where they are recorded but not visible to the agent. Only Hot skills are injected at runtime. Rejected skills never enter the runtime context, so they cannot condition the next round's distillation.
  - **Gate 1 (Cold→Warm), a conjunction of three critics:** (i) SchemaCritic, a deterministic check that the frontmatter fields exist and are correctly typed; (ii) **ExecCritic, a single-skill A-B replay on a held-out split: pass iff R(M ∪ {s}) ≥ R(M)**. A tie is enough, because "the estimate is noisy"; (iii) AgentCritic, one LLM call that checks for fabricated facts, contradiction with M, or unsafe operations.
  - **Gate 2 (Warm→Hot), "marginal-gain" greedy selection.** It starts from the empty set, repeatedly adds the Warm candidate with the largest *estimated* joint gain, and keeps it only if measured joint held-out success f(H) **strictly** improves. It stops when no candidate helps. Each f(H) is the mean of k = 3 held-out replays, and |W| ≤ 15 per round. The authors explicitly call this a heuristic: f is neither known to be submodular nor monotone. **How the marginal gain is computed** (this was the open question from the sweep): it is a measured difference in mean held-out pass rate between H ∪ {s} and H. Gate 2 "reuses the Gate-1 replays" and costs at most |W|−1 joint replays per round, so the "estimated gain" used to *order* candidates is most likely the Gate-1 singleton A-B gain, with one joint replay per candidate in that order. The paper does not say so explicitly. It also does not say whether "starting from the empty set" means rebuilding Hot from scratch each round, or adding to the existing Hot pool, which grows 5→15→25→30→37. The second reading fits the table better, and under it **existing Hot skills are never re-validated**.
- **Splits (Terminal-Bench 2, stratified by difficulty):** Event-50 is used for distillation and evolution and for the main table. Holdout-14 is used **only** for the gate replays and the marginal-gain estimates. Test-25 is reserved for final evaluation. The authors say the Event numbers are "an optimistic upper bound".

## Results (primary backbone Hy3; 5 rounds; k = 3 rollouts; deterministic TB2 verifier)

- **Event-50, pass@1:** Seed (3 hand-written skills) 46%. Ungated 48 → 60 → **62 (R3, 105 skills)** → 52 → 50% (R5, 179 skills). VaG 52 → 58 → 62 → 68 → **72% (R5, 37 Hot skills)**. Hard tier at R5: VaG 59% vs Ungated 35%. Tokens per trial: VaG 0.77–0.94M vs Ungated up to 1.30M.
- **Statistical caveat stated by the authors:** the 95% Wilson bands are about 30pp wide and overlap at intermediate rounds, so per-round comparisons are underpowered. The claim rests on the *shape* of the trajectories (monotone vs single-peaked). This is one seed, one backbone, and one benchmark split.
- **Rollback (Ungated R5, 50%):** removing the 8 harmful source skills gives 52% (Table 1) and recovers 1.7pp of the 12.3pp peak-to-R5 drop (Fig. 4). An oracle that removes the full lineage recovers a further 5.0pp (6.7pp in total). 5.6pp remains unrecovered. VaG beats the oracle by 15.3pp.
- **Ablation (R5, Event-50):** removing the holdout replay costs −10pp (the pool grows to 45). Removing the marginal-gain gate costs −8pp (the pool grows to 58). Removing the semantic check costs −4pp. Removing schema validation costs −2pp.
- **Cross-backbone, frozen R5 Hot pool on Test-25, Seed → VaG:** Hy3 32→44, DeepSeek-V4-Pro 32→40, GPT-5.4 44→56, Claude Sonnet 4.5 48→56, Qwen3.6-35B-A3B 36→52 (+8 to +16pp). **The Ungated pool is not reported on Test-25 or across backbones**, so the held-out gated-vs-ungated comparison appears only on NL2Bash.
- **Cross-benchmark, InterCode NL2Bash (200 tasks):** Seed 57.5%, Ungated 65.5%, VaG 69.0%. Ungated still beats Seed here, which the authors attribute to shallow contamination on single-step tasks.
- **Not head-to-head with ACE or AHE:** different backbone, task suite, and number of rounds.

## Overlap vs HeritAgent chain

| Element | Coverage |
|---|---|
| 1. Lifetime-trajectory mining | **Full.** Skills are distilled each round from the agent's own TB2 trajectories. |
| 2. Somatic/germline separation | **Absent.** Cold is a quarantine tier: candidates are recorded but not expressed. It is **not** a somatic store, because Cold skills are not used during the lifetime. Hot is both the expressed store and the persistent store. There is no boundary between what one agent uses and what descendants inherit. Structurally, Cold→Warm→Hot is a promotion pipeline (as in LOGOS), not a soma/germ split. |
| 3. Typed executable genome | **Partial (weak).** Skills have a schema-checked, "correctly typed" frontmatter, and the `trigger condition` is a primitive regulatory element. But the bodies are free-form natural-language advice, not executable code. There is no versioning, no policies or regulatory genes, and no whole-agent spec. |
| 4. Causal Inheritance Gate | **Partial (strong). This is the closest overlap with CIG recorded so far.** ExecCritic is an interventional add-one contrast on held-out tasks, R(M∪{s}) − R(M). That is the same shape as SPEC §9's C(t\|G) = E[F(G∪t) − F(G∖t)], and it is a **prerequisite** for persisting a skill. Gate 2 adds a measured joint-interaction check, which roughly corresponds to CIG's interaction stage. Gaps relative to CIG: no replay-reproducibility stage on the source environment; no attribution (Shapley or similar) beyond greedy sequential gains; ties pass Gate 1 (≥) and there are no CIs or significance thresholds (14 tasks, k = 3); no per-task or protected-set regression check (only aggregate non-degradation); admitted Hot skills are apparently never re-tested; held-out tasks come from the same benchmark distribution; and the gate is for **runtime admission**, not heritability. |
| 5. Selective assimilation | **Partial (strong as a mechanism).** Selective, evidence-gated admission into the persistent pool is fully implemented and empirically beats unconditional admission. What is missing is the target: the pool is a single runtime context, not a heritable genome distinct from lifetime state, and nothing is assimilated *into* a genome structure. |
| 6. Multi-generational, frozen weights | **Partial.** Weights are frozen (prompt injection only; closed models used). Generations: 5 evolution rounds of **one** agent. "Descendants" are skills, not agents. The one inheritance-like event is a single-shot transfer of the frozen pool to 4 other backbones. There are no iterated agent generations, population, or selection. |

## Limitations (not stated by the authors, but visible in the paper)

- Single primary backbone (Hy3), one benchmark split, 5 rounds, k = 3, small splits (50/14/25). The authors admit per-round tests are underpowered.
- The headline 72% is on the distillation split. On the true held-out Test-25 the paper reports only Seed vs VaG, not Ungated.
- The gate's own decisions use 14 holdout tasks × 3 replays, and Gate 1 admits ties. False admissions and false rejections are likely and are not quantified.
- The "irreversibility" claim is an inequality argument plus one oracle-cleanup experiment. The unrecovered 5.6pp is not further explained: is it distillation drift, or state baked into later skills?
- The supplement is not on arXiv, there is no code release, and the Hot-pool re-validation semantics are ambiguous.

## Consequences for HeritAgent

- **The novelty position moves.** Ledger §3 currently lists "CIG as a prerequisite for assimilation (not post-hoc curation)" as ours to defend. VaG already implements and motivates *pre-commit* gating of trajectory-mined skills with a held-out interventional add-one test plus an interaction check. It also shows, on a small scale, a monotone gated curve, a smaller pool, and positive cross-backbone transfer. These results pre-empt parts of **H2** (gate vs automatic persistence), **H5** (less bloat than unrestricted accumulation) and **H4** (cross-backbone transfer of a gated store, though they never compare it with the ungated pool across backbones). What remains ours is the integration: an explicit somatic/germline split, a typed executable versioned EAG, a CIG with replay, attribution, held-out generalization and regression stages, gating of **heritability** rather than runtime admission, and genuine multi-generational populations. Recommended threat level: **medium-high** on element 4 / H2 / H5 specifically; **low** on the full chain.
- **Add a VaG baseline arm.** For example, a variant of baseline C (Persistent Skill Agent) that uses VaG's Gate 1 + Gate 2 with the same holdout budget. Without it, a reviewer can argue that CIG's gains over arm C are already explained by VaG-style admission control. The comparison that matters is CIG vs VaG on descendant performance, regression rate, genome size and descendant adaptation cost **across generations**, which VaG never measures.
- **Lineage provenance.** VaG's central observation is that libraries do not record the distillation context, i.e. which skills were in context when a new skill was written. HeritAgent's Lineage Graph (SPEC §13) should record, for each trait, the germline/somatic traits present when it was mined. Then the "descendant contamination" of an assimilated trait can be measured across generations. The analogous HeritAgent claim, that a bad germline trait propagates to descendants and is irreversible, should be tested, not assumed.
- **CIG design lessons.** (a) Do not admit on ties: require a positive contribution estimate with an uncertainty bound, and report false-admission rates. (b) Re-validate already-assimilated traits when the genome changes, because VaG apparently does not. (c) Use separate gate-holdout and final-test splits, as VaG does (Holdout vs Test). This is already implied by SPEC §9 and §24.
- **Phrasing.** VaG uses "promotion", "trust tier", "descendants" and "inherited" for skill lineages within one lifetime. In writing, gloss theirs as *runtime admission control for a single agent's skill pool* and ours as *heritability gating for a germline genome*.
